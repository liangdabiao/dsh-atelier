# 母题工作台工作流

## 核心原则：一次采集，两次使用

同一条对标作品，创作前采一次拿结构与原话作为**可回溯证据**，发布后按作品 ID 再采一次拿**真实指标增量**。
经验规则要锚在可回溯的公开数据上，而不是模型对文本的主观总结。

## 主链路

1. **信息来源**：`radar` 从 TikHub 白名单端点取热榜 / 趋势词 / 搜索联想 / 话题 / 对标账号作品谱 / 作品详情；
   `evidence` 补评论原话与详情。每条信号与证据都记 `endpoint / params / fetchedAt / rawRef`。
2. **拆解** `deconstruct`：钩子、结构、证据、模式，逐项引用 `evidence_id`；同时记录对标作品 baseline 指标。
3. **差异化方向** `angles`：≥3 个真正不同的方向，人工选一；禁止同义替换。
4. **出稿** `draft` → **体检** `review`（只做质量诊断，不预测表现）→ **迭代**：版本只追加、不可覆盖。
5. **多渠道派生** `derive`：同一母题派生到不同平台，各自可回溯。可选 `image` 生封面。
6. **发布前盲判断** `predict`：锁定并生成 `integrity_hash`，锁定后**不可覆盖**，否则校准失去意义。
7. **数据反馈** `watch` 登记作品 → `feedback` 按 ID 在 T+1/3/7 回查真实指标 → `snapshots(origin=api)`；
   拿不到的平台用 `manual` 补录，标记 `origin=manual`，**两类数据不混算**。
8. **复盘** `retro`：锁定预测 vs 实际、对标作品 baseline 增量；只做对照，不补造预测、不把相关性写成因果。
9. **规则闭环** `rule`：propose → **人工审核** → active/rejected；只有 active 规则会进 Skill addendum 影响下一轮生成。

## 数据纪律（铁律，有实测依据）

- 先拿真实数据再下结论；**禁止编造笔记、评论、互动量、本人经历或数据**，缺口标「待补充 / N/A」。
- 平台数据失败时明确说「未取到」，**不要用 web 搜索结果冒充平台数据**，也不要用模板稿冒充成稿成功。
- 公开互动数 ≠ 平台后台的完播率 / 粉丝画像；抖音无通用 analytics、billboard 分析只覆盖上榜作品、小红书详情需 `xsec_token`、视频号/公众号基本拿不到发布后指标。
- 端点会漂移：以线上 OpenAPI 为准，不照抄静态映射表；404 时看插件给出的相近路径建议，不静默换路径出数。
- 评论采集、批量账号作品、生图等高成本动作要**显式确认**；按端点限流（多数 5 req/s），429 按 Retry-After 退避。

## 边界

- 不做自动发布、ASR、多用户、云同步、全量端点浏览器。
- 模型不可用时，依赖模型的动作（拆解/方向/出稿/体检/派生/预测）显式失败；采集、证据、登记、回查、复盘、规则审核不依赖模型。
- 数据目录 `$DSH_HOME/atelier/`，读写只走 `atelier` / `atelier_query` 工具与插件页面，不要用 bash 直接改。
